# Knowledge

- 2026-03-24 — In this GSD worktree environment (`.gsd/worktrees/*`) with Node `v25.8.1` + Vite `v7.3.1`, local Vite runtime commands can fail with environment/path-specific errors (`dependency optimization ... reading 'imports'` during `npm run dev:client`, and emitted chunk `fileName` path errors during `npm run build`). For slice execution inside auto-mode worktrees, rely on Vitest verification surfaces for UI logic unless runtime browser UAT is explicitly required in a non-worktree runtime environment.
- 2026-03-24 — For cross-floor directions, compute connector `up/down` language from resolved floor numbers (using `floorMap` when available, with `floorId` fallback) and carry `floorId` + `floorNumber` on every `DirectionStep`. In UI rendering, group by contiguous floor runs and only show floor headers when there is more than one section. This avoids incorrect vertical wording when IDs are not ordered and preserves flat rendering for single-floor routes.
- 2026-03-24 — In Hono route handlers, `c.json(payload, status)` is typed against a literal `ContentfulStatusCode` union; if status comes from a custom error class, type that status as a literal union (e.g. `400 | 404`) instead of `number` to avoid TS2769 under strict typecheck.
- 2026-03-24 — `NavNode` connector fields are optional, and reducer-style `{ ...node, ...changes }` updates cannot reliably clear them to “unset” under strict optional typing. For server-driven connector unlink patches, rebuild the node object without connector keys (strip + conditional re-add) and replace full node entries instead of merging partial updates.
- 2026-03-24 — For admin connector linking UI, treat `/api/admin/connectors/link` as server-authoritative and patch both active-floor editor state and cached multi-floor `navGraph` from `updatedNodes`. Do not attempt local optimistic reciprocal edits; they drift on relink/unlink stale-link cleanup paths.
- 2026-03-24 — GPS floor bounds must be handled as an atomic tuple: accept either all four numeric values (`minLat`, `maxLat`, `minLng`, `maxLng`) or all four nulls to clear; reject partial tuples (`GPS_BOUNDS_INCOMPLETE`) and invalid ordering (`BOUNDS_RANGE_INVALID`) before persistence.
- 2026-03-24 — Keep `/api/map` floor `gpsBounds` complete-only and patch editor graph state from `PUT /api/admin/floors/:id/gps-bounds` responses by `floorId` (including campus floor). This prevents partial calibration drift and gives S27 a trustworthy projection contract.
- 2026-03-25 — In shell verification commands that use `awk` inside a quoted `bash -lc '...'` string, escape field variables as `\$2` (not `$2`), otherwise the shell expands `$2` before awk sees it and checkpoint-hash extraction silently degrades to a wrong value.
- 2026-03-25 — When `useGeolocation` resolves browser APIs internally, memoize the resolved adapter (`options.geolocation ?? resolveNavigatorGeolocation()`) before using it as an effect dependency; recreating adapter objects each render can cause repeated watch restarts and React maximum-update-depth noise in browser runs.
- 2026-03-25 — For Konva overlay component tests in this codebase (e.g., GPS marker/ring layers), assert React element props (`Circle` name/x/y/radius/strokeWidth) directly instead of DOM queries; this keeps tests deterministic without requiring canvas rendering harnesses.
- 2026-03-25 — For hook-heavy UI overlays that are awkward to mount in jsdom (like SearchOverlay geolocation states), `renderToStaticMarkup` plus explicit text/attribute assertions is a reliable way to verify fallback copy, button disablement, and manual-control continuity.
- 2026-03-25 — In Konva multi-touch handlers, compute stage-local touch midpoint from `stage.getAbsoluteTransform().copy().invert().point(...)` **before** mutating stage state, then apply scale → rotation → position recalculation in that order. Re-introducing separate midpoint `dx/dy` pan deltas double-counts movement and causes focal drift.
- 2026-03-25 — Milestone closeout quality gates depend on slice-level `S##-SUMMARY.md` artifacts. Task-level summaries alone are not enough for a clean audit verdict; backfill missing slice summaries proactively to avoid `needs-attention` closeouts.
- 2026-03-25 — The prescribed code-diff check `git diff --stat HEAD $(git merge-base HEAD main) -- ':!.gsd/'` fails in repositories that use `master` without a `main` ref. For auditability, run the prescribed command first, then explicitly fallback to `origin/master` merge-base and record both commands/results in the milestone summary.
- 2026-03-26 — In this repo, slice verification commands invoke mobile tests as `npm --prefix mobile run test -- mobile/...`. To make those filters resolve, run Vitest from repo root (`--root ..`) with `mobile/vitest.config.ts` and restrict includes to `mobile/**/*.test.ts`; otherwise Vitest treats `mobile/...` paths as non-existent when rooted at `mobile/`.
- 2026-03-26 — With mobile TypeScript configured for `react-native` + Node typings, `typeof fetch` mocks can become incompatible due differing overloaded signatures/AbortSignal types; use a narrow local `Fetcher` alias (`(input: string, init?: RequestInit) => Promise<Response>`) and cast `signal` to `RequestInit['signal']` at the fetch boundary to keep mobile typecheck stable.
- 2026-03-30 — In mobile `MapViewport` gesture handlers (React Native `PanResponder`), use `useCallback` to stabilize callback references and include all callbacks in memo dependency arrays; omitting them causes stale closure warnings and incorrect gesture behavior on re-render.
- 2026-03-30 — Bootstrap failure diagnostics should carry `phase` (which step failed) and `endpoint` (which URL) metadata from the API client into the startup state machine and into rendered error copy; this makes startup failures actionable without requiring remote debugging on device.
- 2026-03-30 — Mobile NavGraph normalization must preserve optional connector fields (`connectsToFloorId`, `connectsToNodeId`, `connectsToBuildingId`) as `undefined` — not `null` and not filled defaults — to match the `NavGraphSchema` optional field contract; TypeScript's `strictNullChecks` will catch mismatches but only if the normalizer doesn't silently coerce.
- 2026-03-30 — Transform helpers in `mobile/map/mapTransform.ts` should be pure functions that take current state + delta and return new state (not mutate in place); this makes focal-point invariance testable in isolation from gesture event timing and prevents NaN/drift from mutating shared state.
- 2026-03-30 — For high-frequency device updates (GPS position ticks at ~2s intervals), use a mutable ref pattern — write every update to a `useRef` immediately; commit a stable `useState` snapshot only after each processing pass completes. This prevents React render thrashing while keeping state reactive for the UI. The pattern: `const posRef = useRef(initial); const [snap, setSnap] = useState(initial); useEffect(() => { posRef.current = newVal; setSnap(newVal); }, [newVal])`.
- 2026-03-30 — For async side effects triggered by state transitions (e.g., reroute on phase change), use `useEffect([guidanceState.phase], ...)` keyed on the stable render-committed value (phase), not the ref. Read from ref inside the effect if needed. This avoids stale closures that plague direct ref polling.
- 2026-03-30 — When device APIs (geolocation, magnetometer) must be testable, define `PositionReader` and `HeadingReader` interfaces and inject them as options. Tests provide fake implementations; production uses default classes. This is the correct mobile testability pattern for hardware-dependent hooks.
- 2026-03-30 — For heading/angle EMA smoothing with wraparound at 0°/360°, use shortest-path logic: `const delta = newVal - smoothed; if (Math.abs(delta) > 180) smoothed -= Math.sign(delta) * 360; smoothed = alpha * newVal + (1-alpha) * smoothed`. This prevents 360° oscillation at cardinal boundaries.
- 2026-03-30 — `bearing(ax, ay, bx, by)` for screen-space navigation: formula is `atan2(dy, -dx) * (180/π) + 270` normalized to [0, 360). The `-dx` (not `dx`) is the x-axis mirroring correction for screen-space y-inversion. Both `atan2(dx, -dy)` and `atan2(dy, dx)` produce 90° rotation on east-west; test against known cardinal cases to catch this.
- 2026-03-30 — When mobile Vitest runs fail with "describe is not defined" in isolated file mode, the globals environment is not being applied. Run tests via `npx vitest run` from the mobile directory root with the full config, not via `npm test -- --run <file>` from repo root. The vitest config must include `setupFiles` and globals configuration.
- 2026-03-30 — Vite 7's oxc TSX transform backend cannot parse `import type` syntax in `.tsx` files when aliased via `vite.config.ts` React plugin. If TSX component tests fail to transform, this is the root cause. Fix: use `import React from 'react'` style imports instead of `import type`, or await a Vite 7 oxc fix.
- 2026-03-30 — Mobile hook integration tests (React rendering) are blocked by pre-existing React 19 / @testing-library/react@16.3.2 incompatibility in Vitest jsdom. When this is encountered, fall back to: (1) pure function tests for all logic, (2) interface contract tests with fake implementations, (3) typecheck verification. - 2026-03-30 — For heading-aware map rotation, phase-gate the heading signal: pass `null` during idle to preserve manual map exploration, pass actual heading only when `guidanceState.phase !== 'idle'`. This prevents device heading from interfering with user-controlled orientation before guidance starts.
- 2026-03-30 — When combining multiple rotation sources (manual + heading), use cumulative composition: `rotateZ: ${manualDeg + headingDeg}`. Preserve each rotation source through all transform mutations (manual rotation via `applyPinchRotate`, heading via `applyHeadingRotation`) to prevent value loss during pan/pinch gestures.
- 2026-03-30 — For floor boundary detection in guidance hooks, use `useRef<number | null>` to track previous floor without triggering re-renders. Emit transition events only when both current and previous are non-null and different. This decouples detection logic from rendering.
- 2026-03-30 — For floor transition UI banners, initialize useRef on mount and compare against current props each render. Show banner when transition detected, auto-hide after timeout via setTimeout. This state-free approach avoids redundant re-renders from banner visibility state.
- 2026-03-30 — For TypeScript strict mode with optional props like `floorId?: number | null`, introduce a local coercion (`const safeFloorId: number | null = floorId ?? null`) before passing to useRef or setState. This explicit pattern is self-documenting and satisfies strict union type requirements.
- 2026-03-30 — When extracting helpers from component files for testability (like `findNearestNodeOnFloor` from App.tsx), place them in dedicated `hooks/` files. This avoids importing React Native modules in tests and allows unit testing without mocking the entire component tree.
- 2026-03-30 — **`export type` + oxc parser incompatibility**: Vite 6 + vitest 4.x uses oxc in worker processes for ALL transitive module resolution, bypassing user plugins. oxc cannot parse TypeScript `export type` syntax in ANY source file (not just test files). The fix: pair every `export type` with `export const <Name> = undefined as unknown as <Type>` so oxc sees a value export while TypeScript preserves the type. Do NOT remove `export type` entirely — consumers importing types will still work because TypeScript resolves types at compile time. The `export const` is only for runtime JS compatibility. Pattern: `export type Foo = 'a' | 'b'; export const Foo = undefined as unknown as Foo;`
